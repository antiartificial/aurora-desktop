Aurora

A toy desktop operating system built on the argument that the interesting part of a desktop is not the kernel. It is the userspace: a typed message bus, applications described by manifests, and isolation that holds by construction rather than by convention.

01What it is

Aurora is a working desktop built from the inside out. Instead of starting with a bootloader, it starts with the question every modern desktop answers badly: when a program touches your files, what exactly was it allowed to do, who said so, and can you check afterwards?

Every action is a typed verb declared in a manifest. Running one creates a domain — a bubblewrap sandbox with its own subordinate uid, granted exactly the input file and the single output file and nothing else. The identity of whoever asked is stamped by the bus from kernel facts, never taken from what the client claims. The result carries provenance: which app, which verb, which grants, which capability handles, recorded both as a file attribute and as an event in an append-only, tamper-evident log.

On top of that sits a compositor that draws its own desktop, and three different foreign worlds running as guests.

02Goals

  • Isolation by construction. An app gets what its manifest declares plus what you hand it. Not a policy file; the absence of a path in a mount namespace.
  • Everything recorded. If the system did something to a file, there is a log entry and an attribute saying so, and a command that checks the record against the daemon.
  • A trusted path you can believe. Approval prompts are drawn by the compositor and are invisible to client screenshots, so no application can imitate one or watch you answer it.
  • Honest claims. Where a property is not actually enforced, the code, the docs and the command output say so. This page does the same.
  • BeOS heritage, 2026 execution. Haiku's API for applications; a modern text and compositing stack underneath.
  • Bare metal eventually. Today Aurora runs nested inside another compositor. That is the largest remaining gap.

The trusted path is a drawing-order property, not a permission check. Captures are served from the frame before the approval overlay is composited, so a client cannot photograph a prompt even though it can photograph everything else.

09Known defects and limits

Dock labels are invisible on a light background. The label text is near-white by design, which reads well over the dark desktop. Measured over a pure white backdrop, the glass resolves to sRGB (237,241,247) and label contrast collapses to 1.13:1 where WCAG 2 wants 4.5:1. A luminance ceiling with derived constants is specified and being implemented.

One uid owns everything. Domains, the bus, the controller and the compositor all run as the same user. A same-user process can speak to the bus as a domain, and the security story holds against confined applications, not against you. Nothing here defends a domain from its own owner.

A domain is easier to hijack than an unsandboxed process. This one inverted the expectation and was only found by testing it. Yama normally permits ptrace only from an ancestor, so a same-uid stranger cannot touch an ordinary process. It can touch anything inside a domain, because a user namespace grants its owner CAP_SYS_PTRACE within it and bubblewrap always creates one. The bus's ancestry check cannot see this: an injected process descends from the sandbox exactly as it should.

The log is tamper-evident, not tamper-proof. Every record carries a sequence number and the hash of the previous line, anchored by a head file, so deletions, reordering and truncation are all detected. But the hash is unkeyed: anyone who can write the directory can rewrite history and the anchor together. Verified by doing it. Pinning the tip out of band catches it; a real defence needs a key the log writer cannot read.

Agent writes are not staged. The plan promises a copy-on-write snapshot with a reviewable diff. Today an agent's writes land in the real directory, so “writes are allowed freely” is a larger grant than intended.

Residual query leaks. A domain sees only its own files, but the sequence cursor is global, so gaps reveal that invisible entries exist, and saved-query names are listed to every caller.

10Research cited

The visual system is specified from primary sources, with about ninety references in docs/visual-system.md. A selection of the load-bearing ones:

  • Marius Bjørge (ARM), “Bandwidth-Efficient Rendering”, SIGGRAPH 2015 Mobile Graphics course. The dual-filter blur kernels this compositor implements, with the sub-pixel stability tests that justify not replacing them.
  • Jorge Jimenez (Activision Blizzard), “Next Generation Post Processing in Call of Duty: Advanced Warfare”, SIGGRAPH 2014. Considered and deliberately skipped: its Karis average fixes bloom artefacts Aurora does not have.
  • W3C, Web Content Accessibility Guidelines 2.2, 12 December 2024. The relative-luminance and contrast definitions used for the dock contrast measurement and the ceiling that will fix it.
  • Lipshitz, Wannamaker & Vanderkooy, “Quantization and Dither: A Theoretical Survey”, JAES 40(5), 1992; with Ulichney, “The void-and-cluster method for dither array generation”, Proc. SPIE 1913, 1993. Why the dither is zero-mean triangular rather than the uniform additive noise a neighbouring compositor uses.
  • W3C CSSWG, Filter Effects Module. “Filter functions must operate in the sRGB color space” — the reason client translucency stays encoded while our own blur moves to linear light.
  • Dragiçević et al., CHI 2011. The one on-point study of animation curve shape, which favours slow-in/slow-out for its task. Recorded because it complicates rather than supports the ease-out choice.
  • Timothy Lottes (AMD), GDC 2016; and Mikkel Gjøl (Playdead), “Banding in Games: A Noisy Rant”. Precision and banding, behind the decision to store the square root of linear light in ten bits per channel rather than paying for half floats.
  • Debenedetti et al., “Defeating Prompt Injections by Design” (CaMeL), Google DeepMind, 2025. Read for the agent design, and cited for what its guarantee buys only when its structure comes with it — which a general-purpose bus cannot provide.

Two findings worth repeating because they changed decisions. Apple's Liquid Glass is parameterised, in its own private filter surface, as refraction amount and height over a quarter-resolution backdrop driven by a distance field; no verifiable implementation anywhere marches a ray through a volume, so Aurora will not either. And the claim that ease-out “feels faster” has no primary source — it is designer consensus. The preference is implemented because the arithmetic of the first frame supports it, and the documents forbid claiming research does.

Aurora is a research prototype that demonstrates mechanisms and measures their limits. It is not a security boundary against a same-user attacker, and it does not boot. Both of those are stated here for the same reason they are stated in the code.
